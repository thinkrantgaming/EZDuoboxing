# Selectors and control mappings

Two independent configurations determine the result:

1. **Sender `config.local.py`:** which physical button selects which receiver, plus address, port and token.
2. **Receiver controls file:** what each forwarded physical button or stick does on THAT computer.

Steam Input separately controls the local character and suppression layers. Changing receiver keys does not change the local layout.

## Configure destinations and selector buttons

Copy the public template before editing:

```powershell
Copy-Item config.py config.local.py
```

Deck/Linux equivalent: `cp config.py config.local.py`.

```python
TOKEN = 'YOUR_SHARED_TOKEN'
HOSTS = {
    'character_1': {
        'ip': 'RECEIVER_1_IP',
        'port': 50505,
        'button': 'R5',
        'enabled': True,
    },
    'character_2': {
        'ip': 'RECEIVER_2_IP',
        'port': 50505,
        'button': 'L5',
        'enabled': True,
        # 'token': 'OPTIONAL_DIFFERENT_TOKEN_FOR_THIS_RECEIVER',
    },
}
INPUT_SOURCE = 'native'  # Deck only
GRIPS = True
TOUCHPADS = 'pressure'
```

Replace the IP placeholders, keep tokens matched to each receiver, and use:

```bash
python3 deck_sender.py --config config.local.py
```

Or Windows: `py -3.14 windows_sender.py --config config.local.py`.

**Do not put a receiver IP after the script when using this config.** A positional IP selects single-host mode, ignores the config file, and uses R5. `--token` overrides all configured destination tokens. `--port` applies to positional-IP mode; edit each host's `port` in config mode.

### Replace R5/L5

For example, change the two `button` values to `LB` and `BACK`. Update the local Steam Input hold-layer activators to LB and Select/View too. Restart the sender. The included `examples/config.custom-selectors.py` demonstrates this.

Supported selector names (case-sensitive):

```text
A B X Y LB RB LT RT BACK START L3 R3 L4 L5 R4 R5
DPAD_UP DPAD_DOWN DPAD_LEFT DPAD_RIGHT
```

These are physical input names, not keys generated by Steam Input. LT/RT select using the existing trigger press/release thresholds. BACK is Select/View; START is Menu/Start. Different controller legends may use different visible names.

Not selector inputs in this release: keyboard keys, mouse buttons, touchpad sectors, stick tilt directions, Steam/Guide, quick-access, or arbitrary controller devices. Touchpad sectors can still be mapped as remote actions. “Configurable button” means a supported button on the Deck/2026 Steam Controller, not generic HID support.

Each enabled destination needs a unique selector and unique IP/port pair. Disable unused destinations with `enabled=False`. One destination is enough; additional entries can be added, limited by the available selectors and practical usability. Ordinary buttons chosen as selectors lose their normal remote action while they select that host.

### Hold and release behavior

- With no selector held, all remote destinations receive neutral state.
- The first selector held selects a destination. Its own button is consumed.
- While it is held, another selector is an ordinary action on the selected receiver if that receiver maps it. Example: hold R5, press L5 → L5 action on receiver 1.
- Releasing the original selector stops forwarding. Release ALL selectors before choosing another host; the other already-held selector does not immediately take over.
- If multiple selectors arrive together in the same report, neither is selected until released and pressed again.
- After startup/device reconnect, release all selectors to arm routing.

This is hold-to-route, not a toggle. It does not promise an atomic handoff over lossy UDP; unselected hosts receive neutral packets and also have a timeout.

## Receiver controls files

Copy the closest template, then edit it:

```powershell
Copy-Item receiver_config.gamepad.py receiver.local.py
py -3.14 windows_receiver.py --sender-ip SENDER_IP --controls receiver.local.py --token "YOUR_SHARED_TOKEN"
```

For KBM, copy `receiver_config.py`; for mixed input, copy `receiver_config.mixed.py`. The default file remains required beside the core receiver module, even when selecting a custom file. The CLI loads the selected file before creating input outputs. Python configuration files are executable code: load only files you trust. Restart the receiver after changes.

### All remote source names

```text
A B X Y LB RB LT RT BACK START L3 R3 L4 L5 R4 R5
DPAD_UP DPAD_DOWN DPAD_LEFT DPAD_RIGHT
LPAD_UP LPAD_DOWN LPAD_LEFT LPAD_RIGHT
RPAD_UP RPAD_DOWN RPAD_LEFT RPAD_RIGHT
```

The active selector is removed before sending. Opposite grips/selectors may still be actions. `GRIPS=True` (or `--grips`) enables action grip forwarding; turning it off does not disable selector detection. Missing bindings do nothing. Do not put an empty key string in a binding; remove or comment out the binding instead.

### Mapping modes

| Mode | Config fields | Behavior |
|---|---|---|
| `tap` | `keys: [...]` | One keyboard chord, released after TAP_DURATION_SECONDS |
| `hold` | `keys: [...]` | Hold chord for as long as physical button remains down |
| `mouse_tap` | `button: 'left'` | One mouse click; left/right/middle supported |
| `mouse_hold` | `button: 'right'` | Hold mouse button until physical release |
| `gamepad_tap` | `button: 'A'` | Brief virtual Xbox button press; Windows only |
| `gamepad_hold` | `button: 'A'` | Hold virtual Xbox button; Windows only |

Examples to put INSIDE `BINDINGS = {...}`:

```python
'A': {'mode': 'tap', 'keys': ['1']},
'LT': {'mode': 'hold', 'keys': ['shift']},
'LPAD_UP': {'mode': 'tap', 'keys': ['shift', '1']},
'RB': {'mode': 'mouse_hold', 'button': 'right'},
'L4': {'mode': 'tap', 'keys': ['f1']},
```

`['shift', '1']` is a simultaneous chord, not a timed sequence. On a US keyboard layout it normally produces `!`; layouts/game bindings can differ. Hold the modifier before pressing another action for separate-button combinations. Extremely short simultaneous physical presses may be processed in button-name order; use a single chord mapping when ordering matters.

For the direct gamepad equivalent:

```python
'RB': {'mode': 'gamepad_hold', 'button': 'RB'},
'DPAD_UP': {'mode': 'gamepad_hold', 'button': 'DPAD_UP'},
'DPAD_DOWN': {'mode': 'gamepad_hold', 'button': 'DPAD_DOWN'},
```

To make D-pad Down type `s` instead, REPLACE its entry:

```python
'DPAD_DOWN': {'mode': 'hold', 'keys': ['s']},
```

Do not put duplicate dictionary entries for the same source; Python keeps only the last entry. Gamepad targets are:

```text
A B X Y LB RB LT RT BACK START L3 R3
DPAD_UP DPAD_DOWN DPAD_LEFT DPAD_RIGHT
```

A grip/pad sector can target any supported gamepad button, but the virtual Xbox controller has no native rear-grip or touchpad buttons. LT/RT are full press/release outputs in this version. Keys/mouse remain independent of local keys; you need no unused-key workaround.

### Sticks

For keyboard movement and mouse camera:

```python
LEFT_STICK_ENABLED = True
MOVEMENT_KEYS = {'up': 'w', 'down': 's', 'left': 'a', 'right': 'd'}
RIGHT_STICK_MOUSE_ENABLED = True
GAMEPAD_LEFT_STICK = False
GAMEPAD_RIGHT_STICK = False
```

For direct analog gamepad sticks:

```python
LEFT_STICK_ENABLED = False
RIGHT_STICK_MOUSE_ENABLED = False
GAMEPAD_LEFT_STICK = True
GAMEPAD_RIGHT_STICK = True
```

You can independently choose KBM/gamepad behavior per stick. Do not enable both behaviors for the same stick; validation rejects this. Missing GAMEPAD_* options default to False for old configs.

KBM movement uses press/release hysteresis (`MOVE_PRESS_THRESHOLD=0.45`, `MOVE_RELEASE_THRESHOLD=0.35`). Mouse settings control its deadzone, speed, curve and axis inversion. GAMEPAD_* sticks send normalized analog values; mouse settings do not apply to them. Set gamepad deadzones/sensitivity in the game or emulator.

### Touchpad sectors

Sender `TOUCHPADS='pressure'` or `--touchpads pressure` provides four directional sectors per pad. Alternatives are `click`, `touch`, or `off`. Pressure is the recommended initial setting. The initial direction latches until release, so sliding while held does not intentionally issue a new direction on every report. Pressure defaults: press 2500, release 1800. CLI overrides:

```text
--pad-press-pressure 2500 --pad-release-pressure 1800
--debug-touchpads
```

These raw thresholds are device-dependent. Use probe/debug output before changing them. Native pads remain readable when their local Steam Input outputs are disabled.

## Unchanged compatibility defaults

- Port: UDP 50505.
- Receiver timeout: LINK_TIMEOUT_SECONDS = 1.0.
- Tap duration: TAP_DURATION_SECONDS = 0.065.
- Public initial token: CHANGE_THIS_PRIVATE_TOKEN; replace it on both ends.
- Positional sender IP: single receiver selected by R5.
- Existing configs without INPUT_SOURCE retain the Deck's legacy virtual mode; this repository's sample explicitly sets native mode.
- `--deck-ip` is a backward-compatible alias for receiver `--sender-ip`.

To preserve your previous custom config, copy it as a `.local.py` file and select it explicitly. Do not blindly replace it with a new example.
